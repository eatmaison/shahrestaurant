# Taurus Easy4U → Shah drink inventory

The verified Taurus entry point is **Management → Bonnen → Afrekenregels** (settled receipt lines). Choose one closed day on both dates, run the search, right-click the table and choose **Export table to Excel…**. Use the resulting .xlsx in Shah **Admin → Stock → Taurus drink sales**. This is a reviewed import, not a live Taurus feed. Do not use the .xls from Omzet per periode: it is aggregated and cannot be deduplicated by receipt line.

1. Import only files containing Shah sales; the current receipt-line workbook has no reliable venue identifier. Establish a new physical stock baseline and import only sales after that baseline. Do not backfill against counts that already reflect those sales.
2. For each drink choose the correct Stock product, regardless of name. Products left unmapped are not applied. A confirmed mapping is stored for next time. Map only a sale unit that corresponds to one stock unit (e.g. one bottled Fuze Tea); leave glasses, bundles, and taps unmapped until separately measured.
3. Preview before/after counts and verify the date before confirming. The .xlsx is parsed in the browser and is not uploaded. Only five required columns are read; only matched drink details are sent. Customer, employee and payment detail columns are not sent. A repeated settled line never decrements stock twice; changes or shortages halt the complete batch. Loose bottles are depleted first, opening sealed cases only as needed.
4. Stats show imported units, not consumption measurements, and cover only mapped lines actually applied. Negative quantities and discount lines do not automatically add stock; refund and physical return are separate actions.
5. Apply the additive 20261126 migration to a test database and run the test suite before coordinating deployment. No data backfill is included. Verify venue attribution and production scope before any automation. A direct per-receipt sync still requires a supported Taurus interface (or verified partner feed), stable line identity, one-way mode, settlement/reversal semantics, venue filtering, and delta reconciliation. The Closing Report is not a second deduction source.
